# Brainstorming

1. Restate the goal in one sentence. State what cannot be delivered rather than hiding it.
2. List at least five distinct candidate directions. For each, search for prior art and write down what kills it. Killed candidates stay in the document.
3. Ask one hard question at a time. Attach a recommended answer to each. Do not begin work while a question is unanswered.
4. Present the surviving design in sections: product, boundary, falsifiable acceptance criteria, non-goals, risks.
5. Save the design document before any implementation.

Rules: never imply a component is novel when it has ancestors; never turn an unverified claim into a promise; no code in this phase.
